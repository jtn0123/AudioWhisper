## Local validation

- Full `make test`: all 2,974 discovered Swift tests passed after the universal build. The suite includes the busy-menu and stalled-writer recovery regressions. Opt-in real inference/visual tests skip in this ordinary unit run; actual inference was exercised separately.
- Python: 88 tests passed across correction sanitization (19), cache/loading (18), RPC (36), and verification scripts (15).
- Universal `make build` passed at source commit `ea18f8a`. App and uv both contain arm64 and x86_64; the final uv signature verifies and its SHA-256 matches compiled metadata. This is a local development bundle without a Developer ID/notarization.
- After removing obsolete deadline metadata, all 17 focused daemon/transport checks passed and the final app was rebuilt.
- Strict SwiftLint: zero violations across 399 files. Strict Python typing: 11 source files passed.
- Real Parakeet: one actual speech test passed in 36.2 seconds, including pinned-model download/bootstrap/inference.
- Real Whisper/MLX: two actual fixtures passed. Whisper returned “The quick brown fox jumps over the lazy dog.” and correction changed “Their going to the store tomorow.” to “They are going to the store tomorrow.”
- Representative latest timing: explicit runtime refresh 0.668 s, warm reuse 0.00110 s; correction inference 1.366 s; Whisper first/warm transcription 0.834/0.079 s on already compiled models. An earlier first CoreML load took 8.257 s. These are local observations, not product-wide latency guarantees.
- [Actual MLX memory benchmark](bench/model_memory.py) ([recorded results](bench/model-memory-results.json)) alternates pinned Qwen 4B and Gemma 1B models four times. Cache entries remained one, weak references proved replaced models were released, and active MLX memory tracked the selected weights (2,264,693,768 → 735,852,808 bytes). After final release, active memory was 8 bytes and allocator cache 0; RSS fell from 3.11 GB at the first Qwen load to 0.80 GB after release. RSS includes interpreter/library/allocator overhead and does not equal model weight size.

Real-engine checks downloaded public Parakeet v3, Whisper Base, Qwen correction and Gemma benchmark weights into the existing model caches. They did not reset permissions or grant new microphone/Accessibility access. Unit integration tests use synthetic bundled speech, isolated preferences and an isolated delivery store.

## Direct follow-up debugging

After the user requested direct debugging, app samples showed the existing desktop process was still the old launch from 18:18, idle in the normal event loop (35 MB footprint). Fresh native-control sessions still returned `cgWindowNotFound` for AudioWhisper and Chrome. This does not reproduce an app hang.

A new read-only `--diagnose-recording` command runs setup checks and exits before creating the GUI. It is also exercised by the packaged-app CI smoke test. The rebuilt bundle (`74c3b62`) identified itself correctly as `com.audiowhisper.app` and reported Parakeet v3 installed, Python ready, microphone not requested, `readyToRecord=false`, and the next step “Allow microphone access.” This is the diagnostic process's authorization context; it does not establish the old desktop process's permission or prove an actual shortcut/prompt interaction. No new permission was requested or granted.

The first remote runs exposed two additional issues:

- [CI stalled-writer failure](https://github.com/jtn0123/AudioWhisper/actions/runs/37171455489): the test's one-second timeout began before Python startup completed. An explicit two-second startup delay reproduced the failure locally. The corrected test waits for the worker's arrival marker, then applies the short timeout only to the blocked write and restores the normal timeout for the replacement process. All four real-pipe tests pass.
- [Real Whisper failure](https://github.com/jtn0123/AudioWhisper/actions/runs/37171460302): the default Neural Engine computation produced `>>` for the speech fixture on the runner, while Parakeet and MLX correction passed. Explicit CPU/GPU computation transcribes the same speech correctly locally. This follows the [upstream correctness guidance](https://github.com/argmaxinc/argmax-oss-swift/discussions/55); The remote rerun still returned `>>`, so this is not a confirmed remote fix. A cold-cache run and full audio/inference diagnostics are now being used to isolate the failure.

After these changes, the CI-equivalent parallel Swift suite with code coverage passed all 2,974 tests, strict lint passed 401 files, and the universal app was rebuilt. Its bundled uv signature and compiled digest match. The latest source is committed and pushed as `74c3b62`; remote verification is being tracked before final signoff.

The rerun at `74c3b62` passed the remote unit/coverage and lint jobs, but [nightly inference remained red](https://github.com/jtn0123/AudioWhisper/actions/runs/37172015593).
